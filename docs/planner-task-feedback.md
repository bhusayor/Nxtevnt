# Task summary feedback

Latest layout polish: the expanded Milestone summary no longer shows “Your milestones” or its overdue-overlap explanation. Expanded Milestone and Task headers have no arrow; only the compact panel keeps its right-facing expand arrow. Both header controls and the animated toggle behaviour remain intact.

The event Tasks page opens with side-by-side Milestone and Task summary panels. Milestones lead by default: their panel is expanded, while Task shows compact status counts. Clicking either panel header expands that panel and compacts the other. Task expanded shows exactly five cards, in this order: To do, In progress, Blocked, Completed, Overdue. Per the latest feedback, the task-count heading and standalone overdue-overlap sentence are removed from both task states. The older Total/Ongoing/Upcoming labels from the reference are not reintroduced.

The completion-bar experiment was reverted at the user's request. Compact Task again shows the previous five pastel status pills, with no completion bar, fraction, percentage or flat legend. The expanded five-card view, milestone-first default, earlier transition fixes and saved task completion states are unchanged.

The first four are mutually exclusive statuses and sum to the task total. Overdue is a separate red date-based alert, not a status. Its count includes unfinished tasks due before today; tasks due today, invalid/missing dates, and completed tasks are not overdue. Expanded To do and In progress cards retain their two-word overdue counts (for example, “15 overdue”); compact Task pills show only the label and status count, with no extra overdue annotation. Task footers otherwise use “Not started”, “Work underway”, “Awaiting input”, “All done” and “Past due” (“Nothing overdue” for zero). Milestone footers use “Event stages”, “Past due”, “Work remaining” and “All done”. Every footer is two words and displays fully on one line, with no ellipsis, truncation or hover dependency. Both summaries share the same blush-rose Overdue footer and compact-row palette with dark berry text and a subtle rose border; normal-text contrast exceeds 4.5:1.

Counts cover the full event plan and do not change when searching or filtering the milestone list or Kanban board. Legacy ongoing/review values map to In progress, legacy done tasks map to Completed, and archived/canceled tasks are excluded. Calendar boundaries use the event timezone with Africa/Lagos as the fallback. No records or statuses are rewritten.

The panels immediately trade column widths over 320ms. The destination card/pill layout is rendered on the first frame, with each content area held at its final width (accounting for the grid gap, panel padding and borders). This removes the intermediate stage where compact pills stretched across the growing panel before changing into cards. There is no fade-out or blank waiting stage. Content width locks are released when the panels reach their destination; the frame then eases to its measured final height over 240ms. The frame stays constrained during the width change, preventing expanded cards from briefly stacking tall inside a narrow panel. Milestone has slightly more horizontal space in both views (about 76% expanded and 28% compact). Summary cards do not replay their entry/count animation on each toggle. Transition-end handlers have timer fallbacks; rapid switching, resize and unmount clear pending work. Small screens and reduced-motion preferences switch immediately. Labels and footers use 14px text. Container-aware grids keep the cards readable; small screens stack both panels and wrap the cards. The milestone/board structure, milestone filter and comments are preserved.

Milestone expanded shows Total milestones, Overdue, Open and Completed. Open + Completed equals Total; Overdue is an alert subset of Open. A milestone is completed only when it has at least one active task and every active task is completed. An open milestone is overdue when its valid target date is past or an unfinished task is past due. Empty milestones are open, and completed milestones are never overdue even if their target date has passed. Tasks without a valid milestone do not inflate milestone counts.

Read-only fixture coverage lives in `tests/task-summary.test.cjs`: status totals and overdue overlaps, seven-task and 16-task examples, legacy statuses, empty/singular states, invalid dates, completed/blocked due dates, expanded/compact rendering, both toggle directions, accessible control bindings, motion/reduced-motion styles and filter-independent integration with TaskWorkspace.

`tests/task-summary-motion.test.cjs` covers the immediate destination layout, exact final content widths in both directions, measured height lock, transition-end filtering and fallbacks, rapid reversal, responsive/reduced-motion switching, resize and cleanup with deterministic hook fixtures.

## Milestone actions and moving tasks

Milestone headers expose Add task, Edit and Delete directly, including while collapsed. The milestone three-dot menu, Duplicate, Move up and Move down actions are removed. Drag-and-drop and keyboard handle reordering are retained. Delete still requires confirmation and keeps the milestone's tasks in Other tasks.

Milestone rows have a rose-tinted header whenever an unfinished active task is past due. Nonempty milestones whose active tasks are all complete have a sage-green header and green title. There is no left accent stripe; all sides retain the same thin card border. An overdue count or “All done” badge communicates the same state without relying on colour. Empty milestones stay neutral, invalid dates do not trigger red, and a milestone target date alone does not trigger row colouring. Row state uses the full milestone, even when a search/status filter hides some tasks, and remains visible when collapsed. Checking off or reopening tasks updates the row immediately. Archived/canceled tasks do not affect these colours or the active-task count.

Each task row has a visible Move action. The same milestone picker is available on board cards and from task details. The modal lists every milestone plus Other tasks, marks the current location, and lets the planner select a destination before confirming Move task. Selecting a destination is only a draft; Cancel/close makes no changes. A successful move preserves task ID, status, due date, assignee, visibility, details and comments, and opens the destination milestone. Moving from task details preserves an unsent comment.

Missing tasks/destinations, cancelled events and failed storage writes do not silently complete a move. Failed saves keep the modal open with an error. `tests/task-actions.test.cjs` covers the visible row controls, confirmation/cancel behaviour, real move projection in isolated memory storage, picker entry points, stale/failure paths, metadata preservation, and cross-event isolation.
